# CSSOM Module 实现计划

> **项目**: MusKitty Phase 2 子阶段 4
> **日期**: 2026-07-22
> **状态**: 待 review
> **规范源**: `d:\csswg\cssom-1\Overview.md`、`d:\csswg\css-syntax-3\Overview.md`

**Goal**: 新建 `muskitty-cssom` crate，实现 CSS Object Model 的数据结构层——将 css-parser 的语法层结构（`Stylesheet`/`Rule`/`AtRule`/`QualifiedRule`/`Declaration`）映射到 CSSOM 语义层（`CSSStyleSheet`/`CSSStyleRule`/`CSSMediaRule`/`CSSStyleDeclaration` 等），并提供序列化。为子阶段 5 Cascade 提供强类型的 CSS 规则树。

**Architecture**: 语法→语义映射层。css-parser 产出语法层 `Stylesheet`（§5.2），CSSOM crate 将其转换为 CSSOM 语义层 `CSSStyleSheet`（§8.1）。转换是 one-way 的（语法→语义），不做反向生成。序列化遵循 §3 + §8.4-§8.6。

**Tech Stack**: Rust stable，零 unsafe，零 C/C++ 依赖。依赖 `muskitty-css`（facade，提供 css-parser 的类型）。MSRV 1.82。

---

## 范围边界

### 做什么

1. **CSSStyleSheet** — 顶层容器，含 rules 列表 + 元数据（location/media/title/disabled flag 等，§8.1 L697-830）
2. **CSSRule 枚举** — §8.4 的 rule 类型层次：
   - `CSSStyleRule`（§8.4 L1641）— selector prelude + declarations + nested cssRules
   - `CSSImportRule`（§8.4 L1679）— href + media
   - `CSSMediaRule`（§8.4 L1699）— media condition + cssRules
   - `CSSNamespaceRule`（§8.4 L1798）— namespaceURI + prefix
   - `CSSLayerBlockRule`（§8.4）— name + cssRules
   - `CSSLayerStatementRule`（§8.4）— nameList
   - `CSSSupportsRule`（§8.4）— condition + cssRules
   - `CSSContainerRule`（§8.4）— condition + cssRules
3. **CSSStyleDeclaration** — §8.6 ordered declarations list + readonly flag
4. **CSSDeclaration** — §8.5 name + value (component values) + important flag
5. **转换层** — 从 css-parser `Stylesheet` → CSSOM `CSSStyleSheet`
6. **序列化** — §3 common serializing idioms + §8.4-§8.6 rule/declaration/block 序列化

### 不做什么（明确推迟）

| 项目 | 原因 | 推迟到 |
|------|------|--------|
| mutation API（insertRule/deleteRule） | Cascade 只读，不需要修改 | 按需 |
| CSSStyleSheet construction（JS API） | 浏览器 JS 层，非引擎核心 | DOM 集成阶段 |
| shorthand 序列化合并 | 需要属性数据库（哪些 longhand 映射到哪个 shorthand） | 子阶段 5 Cascade |
| CSSKeyframesRule / CSSKeyframeRule | 动画，不影响布局 | 按需 |
| CSSFontFaceRule | 字体加载，不影响布局 | 按需 |
| CSSPageRule | 分页打印 | 按需 |
| CSSCounterStyleRule / CSSPropertyRule / CSSFontPaletteValuesRule | 高级特性 | 按需 |
| MediaList 接口 | 简化为直接存 component values（media query 解析/求值推迟） | 子阶段 5 |
| CSSOMString 类型 | 直接用 Rust `String` | — |
| computed flag / owner node / updating flag | DOM 集成相关 | DOM 集成阶段 |

### 关键设计决策

**Rule 类型用枚举还是 trait 对象？**

用枚举 `CssRule`。理由：
1. Rust 的 enum 比 trait object 更符合值语义，pattern matching 更清晰
2. CSSOM 的 rule 类型是固定集合（规范枚举的），不需要开放扩展
3. 避免 `Rc<RefCell<>>` 的所有权复杂度（枚举可以直接拥有子数据）
4. 序列化用 match 分发，比 dynamic dispatch 更直观

**嵌套规则如何处理？**

CSS nesting（§8.4 CSSStyleRule 有 cssRules）直接在 `CssStyleRule` 里存 `Vec<CssRule>`。css-parser 的 `QualifiedRule` 已有 `child_rules` 字段（§5.2），转换时直接递归。

**Declaration 的 value 存什么？**

存 `Vec<ComponentValue>`（直接复用 css-parser 的类型）。不做值类型化（那是 muskitty-css-values 的工作），CSSOM 层只关心声明的结构（name + value tokens + important）。

**转换层是 one-way 的吗？**

是的。语法→语义是 one-way 转换。转换后 CSSOM 树独立存在，不反向引用 css-parser 的 `Stylesheet`。这避免了生命周期耦合。

## OM-4: 从 css-parser 转换

**规范**: CSSOM §8.4 L1627-1634 (parse a CSS rule) + §8.6 L2338-2349 (parse a CSS declaration block)

/// 从 css-parser 的 Stylesheet 转换为 CSSOM 的 CssStyleSheet。
pub fn from_stylesheet(ss: &muskitty_css::parser::Stylesheet) -> CssStyleSheet {
    CssStyleSheet {
        location: None,
        media: Vec::new(),
        title: String::new(),
        alternate: false,
        disabled: false,
        css_rules: ss.rules.iter().map(convert_rule).collect(),

}

            // CSSNestedDeclarations，但我们简化为保留在父 rule 的 style 中）

    }

at-rule 分发：
- `"import"` → CssImportRule（从 prelude 解析 href + media）
- `"media"` → CssMediaRule（prelude 作为 condition，block 中的 rules 作为 cssRules）

- `"container"` → CssContainerRule

## OM-5: 序列化

**规范**: CSSOM §3 (L72-167) + §8.4 (L1637-1834) + §8.5 (L2352-2365) + §8.6 (L2370-2414)

### Task 5-1: 序列化 trait + 实现

```rust
pub trait ToCss {
    fn to_css_string(&self) -> String;
}
```

- **CssDeclaration**（§8.5 L2352-2364）：`name: value !important;`
- **CssStyleDeclaration**（§8.6 L2370-2414）：遍历 declarations，join with space。简化版：不做 shorthand 合并（推迟到 Cascade）。
- **CssRule**（§8.4 L1637-1834）：match 分发到各 rule 类型
  - Style：`selectors { decls; nested rules }`
  - Import：`@import url("...") media;`
  - Media：`@media condition { rules }`
  - Namespace：`@namespace prefix url;`
  - Supports：`@supports condition { rules }`
  - LayerBlock：`@layer name { rules }`
  - LayerStatement：`@layer name1, name2;`
  - Container：`@container condition { rules }`
- **CssStyleSheet**：遍历 css_rules，join with newline

### Task 5-2: §3 serializing idioms

- `serialize_identifier(name: &str) -> String`（§3 L84-107）
- `serialize_string(s: &str) -> String`（§3 L127-138）
- `serialize_url(url: &str) -> String`（§3 L144-147）
